# Submission Packaging P0 — Execution Plan

## Task

Submission Packaging P0 — reviewer-ready AquaSentinel 813 hackathon package.

## Goal

Turn the existing accepted Sentinel-2 HAB / water-quality observational-intelligence implementation into a reviewer-reproducible submission that satisfies every blocking requirement in `docs/HACKATHON_SUBMISSION.md` without changing frozen scientific decisions or claiming unfinished Sentinel-1 science.

Primary submission headline:

`Sentinel-2 HAB / water-quality observational intelligence`

Sentinel-1 oil remains a secondary capability until live acceptance and downstream science are complete.

## Inputs

- `AGENTS.md`
- `docs/HACKATHON_SUBMISSION.md`
- `docs/PROJECT_STATE.md`
- `docs/DECISIONS.md`, especially Decisions 050–054
- Accepted Sentinel-2 implementation and evidence for AS-101 through AS-108
- Existing Python 3.11 package under `src/aquasentinel`
- Existing AOI/configuration and public EO retrieval path through CDSE and Microsoft Planetary Computer

## Outputs

- Reviewer-ready end-to-end Jupyter notebook in English
- Root pinned `requirements.txt`
- Exact reproducible reviewer input/retrieval workflow without credentials
- Committed notebook-produced reviewer outputs
- Root README satisfying the official ten-section contract
- Clean installation and run instructions
- Actual-result maps/figures/tables
- Presentation PDF
- Final project title
- Submission summary of at most 2,000 characters
- Verified GitHub evaluator access readiness
- Final theme wording only after organizer confirmation
- Clean-machine reproducibility result
- Final credential/licence/restricted-data audit

## Files Likely to Change

Expected packaging-only paths include:

- `requirements.txt`
- `README.md`
- `notebooks/aquasentinel_hab_water_quality.ipynb`
- `results/submission/` reviewer-facing outputs
- `presentation/` source material and final PDF or an equivalent clearly named submission path
- `docs/SUBMISSION_PACKAGING_P0.md`
- `docs/PROJECT_STATE.md` only when packaging state materially changes
- `docs/HACKATHON_SUBMISSION.md` only when verified readiness states change or organizer facts change

Core scientific modules under `src/aquasentinel` are not expected to change unless a packaging-only defect prevents execution and the change is demonstrably non-scientific.

## Dependencies

Retain existing pinned runtime dependencies:

- `pystac-client==0.9.0`
- `numpy==2.2.6`
- `rasterio==1.4.3`
- `shapely==2.1.2`

Add only reviewer/notebook dependencies directly required to execute and render the submission notebook. No unrelated scientific or geospatial dependency upgrades are permitted.

## Acceptance Criteria

1. `docs/HACKATHON_SUBMISSION.md` is present in the packaging baseline and remains the administrative source of truth.
2. One tracked `.ipynb` executes end to end under Python 3.11 from a clean clone.
3. Notebook narration is English and uses relative repository paths.
4. Notebook follows existing frozen Sentinel-2 policies and reproduces accepted headline quantities without threshold, weight, date, mask, family, recurrence, or interpretation changes.
5. No credentials, private imagery, restricted imagery, raw full scenes, signed URLs or SAS material are committed.
6. Root `requirements.txt` uses exact pins and installs successfully on Python 3.11.
7. Reviewer can reproduce the result using committed small inputs and/or the exact public retrieval workflow without contacting the team.
8. Reviewer-facing example outputs are generated by the notebook and committed.
9. README follows the official ten-section contract in order.
10. README contains exact clone/install/run instructions and expected outputs.
11. Actual-result figures/tables match accepted AS-107/AS-108 evidence and preserve all limitations.
12. Presentation is English, PDF, under 50 MB, actual-result-first, and does not present proposed functionality as implemented.
13. Final project title and <=2,000-character summary remain within accepted scientific claims.
14. Sentinel-1 is clearly secondary/incomplete; AS-202 is not claimed.
15. Hyperspectral is optional enhancement only and is not required for reproduction.
16. Repository access is verified for evaluators before submission.
17. Final theme wording is added only after organizer confirmation.
18. Clean-machine clone -> install -> notebook run -> expected-output verification passes at the exact submission commit.
19. Final history/security/licence/restricted-data audit passes.
20. Submission form requirements and receipt are independently verified before the applicable deadline.

## Scientific Guardrails

Preserve existing language and boundaries:

- HAB-like spectral anomaly
- biological water-quality observational intelligence
- provisional observational screening
- observational recurrence
- monitoring priority / field verification recommendation

Do not claim:

- confirmed HAB or toxic algae
- confirmed toxins or species from AquaSentinel
- measured chlorophyll concentration from the current pipeline
- biological probability, calibrated confidence, sensitivity, specificity or accuracy that has not been established
- safe/unsafe water certification
- automatic plant shutdown
- confirmed petroleum composition or completed oil-slick science
- intake exposure where it remains unavailable
- exact warning lead time where it is not estimable

Accepted unavailable or zero results must remain visible; packaging must not tune them away.

## Risks

- Live catalog/provider changes could make exact EO retrieval unstable.
- Current repository does not yet contain a reviewer notebook or root requirements file.
- Existing accepted evidence is richer than current reviewer-facing artifacts; outputs must be derived without inventing scientific state.
- Theme registration remains externally unresolved.
- Repository is private until evaluator access is explicitly resolved.
- Creator timezone and final team eligibility remain external confirmation items.
- A presentation built before notebook/result freeze could drift from the reproducible workflow.

Mitigation: freeze the reviewer workflow and actual outputs before README/presentation finalization; keep theme wording unresolved until organizer confirmation; preserve accepted science exactly.

## Validation

Packaging quality gates:

```text
python -m pytest -v
python -m ruff check .
git diff --check
```

Submission-specific validation:

```text
python -m pip install -r requirements.txt
jupyter nbconvert --to notebook --execute notebooks/aquasentinel_hab_water_quality.ipynb \
  --output /tmp/aquasentinel_hab_water_quality.executed.ipynb \
  --ExecutePreprocessor.timeout=1800
```

Then verify:

- visible notebook outputs
- expected accepted headline quantities
- committed reviewer output checksums/content
- no absolute machine-specific paths
- no secrets/tokens/query-bearing signed URLs
- no prohibited/restricted large EO files
- README commands from a clean clone
- PDF format/size
- <=2,000-character form summary
- logged-out/evaluator repository access

## Dependency-Ordered Milestones

### SP0 — Authority & external blockers

- Base packaging work on the authoritative submission-contract branch.
- Track creator timezone, eligibility, evaluator access and theme confirmation as external gates.
- Do not invent theme wording.

### SP1 — Reviewer workflow

- Create the end-to-end Sentinel-2 reviewer notebook.
- Add root pinned `requirements.txt`.
- Use public/no-credential retrieval and/or a permitted small deterministic submission input package.

### SP2 — Actual submission outputs

- Generate and commit notebook-produced map/figure/table/machine-readable outputs.
- Verify against accepted AS-107/AS-108 evidence.

### SP3 — README & clean reproducibility

- Rewrite README to the official ten-section contract.
- Run a clean-clone installation and notebook execution gate.

### SP4 — Submission package

- Freeze final title and <=2,000-character summary.
- Produce the presentation PDF from actual outputs.
- Insert official theme only after confirmation.

### SP5 — Release & form gate

- Perform final credential/licence/restricted-data/history audit.
- Verify evaluator access and clean-machine reproduction at exact submission commit.
- Complete form fields/confirmations, attach PDF, submit before verified cutoff and retain receipt.

## Stop Conditions

Stop for owner review if:

- `docs/HACKATHON_SUBMISSION.md` conflicts with any requested packaging action;
- reproducing the accepted result appears to require changing frozen scientific policy;
- public reviewer reproduction would require credentials, restricted data or a new paid provider;
- accepted result values cannot be reproduced without changing the frozen observation/policy contract;
- organizer confirmation materially changes the theme/submission contract.
